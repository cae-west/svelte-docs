## Contributing

### How to Contribute

SvelteKit is open source and welcomes contributions:

1. **Report bugs** — [Open an issue](https://github.com/sveltejs/kit/issues/new)
2. **Fix bugs** — Look for issues labeled "good first issue"
3. **Improve docs** — Edit documentation files and submit PRs
4. **Share knowledge** — Write blog posts, create tutorials, answer questions
5. **Build tools** — Create adapters, integrations, and libraries

### Contribution Guidelines

- [Contributing Guide](https://github.com/sveltejs/kit/blob/main/CONTRIBUTING.md) — How to contribute to SvelteKit
- [Code of Conduct](https://github.com/sveltejs/kit/blob/main/CODE_OF_CONDUCT.md) — Community guidelines
- [RFC Process](https://github.com/sveltejs/rfcs) — Proposing major changes

### Development Setup

Clone the repository and set up your development environment:

~~~bash
git clone https://github.com/sveltejs/kit.git
cd kit
pnpm install
pnpm build
~~~

Run tests:

~~~bash
pnpm test
~~~

## Support and Help

### Getting Help

1. **Check the docs** — Most questions are answered in the official documentation
2. **Search existing issues** — Your question might already be answered
3. **Ask in Discord** — The community is active and helpful
4. **Post on Stack Overflow** — Tag your question with `sveltekit`
5. **Open a GitHub Discussion** — For longer-form questions

### Reporting Bugs

When reporting bugs, include:

- SvelteKit version (`npm list @sveltejs/kit`)
- Node.js version (`node --version`)
- Package manager and version (`npm --version` or `pnpm --version`)
- Operating system
- Steps to reproduce
- Expected vs actual behavior
- Error messages and stack traces
- Minimal reproduction repository (if possible)
